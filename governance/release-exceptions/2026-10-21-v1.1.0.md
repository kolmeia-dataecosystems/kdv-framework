# One-time release review exception — 21 October 2026

## Owner decision

After approving the complete four-language release, the project owner explicitly authorised: “Autorizar exceção só nesta publicação e restaurar as regras”. This exception applies only to the integration of [PR #1](https://github.com/kolmeia-dataecosystems/kdv-framework/pull/1) for Framework 1.1.0.

The sole initial guardian, `ismael-lab`, authored the PR. GitHub cannot count the author's approval as an independent review. The owner's approval is recorded as an exceptional release decision; it is not represented as an independent GitHub review.

## Bounded procedure

1. Save the actual `main` protection configuration and confirm passing `knowledge-check` on the final PR head.
2. Temporarily change only the three independent-review requirements: approval count from one to zero, CODEOWNER approval from required to not required, and last-push approval from required to not required.
3. Integrate this exact checked PR once, without force pushing. Keep status checks, strict branch freshness, administrator enforcement, guardian push restrictions, conversation resolution and the force-push/deletion bans in place.
4. Restore those three values immediately, including if integration fails. Compare the resulting complete protection configuration with the saved configuration before creating the final release.
5. Record the accepted commit and restoration verification in the GitHub release notes. The website must import that accepted `main` revision explicitly.

This decision does not authorise an exception for any later PR. The permanent policy remains [main-protection.json](../main-protection.json), and the single-guardian limitation in [GOVERNANCE.md](../../GOVERNANCE.md) still applies. A second authorised guardian remains the normal way to enable independent review of guardian-authored changes.
