# Bounded release acceptance — Framework 1.2.0

## Owner authorisation

On 22 October 2026, after directing functional terminology, optional implementation examples and a pause of the website Implementation section, the owner authorised: “Depois disso está autorizado a fazer tudo que é necessário, inclusive todas as aprovações necessárias, para subir isso como a mais nova versão nos 2 repositórios correspondentes ao site e ao conteúdo da documentação”.

This is the human owner's acceptance decision for this coordinated publication. It is not an independent GitHub review and does not reuse the separate 1.1.0 exception. The sole guardian remains `ismael-lab`; no additional access or bypass actor is added.

## Procedure if independent review blocks the integration

1. Save the complete effective main protection configuration. Check the final PR SHA, passing `knowledge-check`, current base and unresolved conversations.
2. Change only the approval count, CODEOWNER-review requirement and last-push-review requirement for this integration. Keep status checks, strict freshness, administrator enforcement, guardian push restrictions, conversation resolution, linear history and the force-push/deletion bans enabled.
3. Squash-merge only the exact checked release PR. Restore the three review requirements immediately using `finally`, whether the integration succeeds or fails.
4. Compare the complete effective policy before and after. Tag and release only after verified restoration, and record the accepted SHA and policy result in the release notes.

The permanent policy in [main-protection.json](../main-protection.json) is unchanged. This decision grants no exception for a later publication. If the operation is rejected by approval review, preserve the completed reviewable changes and request the specific missing authorisation rather than weakening another protection.
