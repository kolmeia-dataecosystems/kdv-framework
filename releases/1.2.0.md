# Framework 1.2.0

22 October 2026 · compatible knowledge update.

The framework now describes implementation support through functional capabilities rather than named tools or product modules. The glossary adds nineteen technical capabilities and six functional areas in English, Brazilian Portuguese, European Portuguese and Spanish. Roles and implementation guidance use the same vocabulary.

KDV Studio/Cloud appears as one optional software example that can bring together those functional areas. Applying the method does not require that example, a particular supplier or a commercial service. Technology selection follows the use case, decision rights, controls and evidence.

The original commercial-name/function correspondence table is retained as an editorial reference under `references/`, outside the website's published content inventory. It is not an endorsement, open-source licence inventory or readiness assessment.

## Compatibility and validation

The six anatomy concepts, five operating layers, preparation and four lifecycle stages, responsibility model, existing guide URLs and twenty template paths are retained. The inventory contains sixty guides in four languages and four existing localized diagrams. Original content remains CC BY 4.0.

`node scripts/check.mjs` validates the inventory, release labels, links, SVG safety, generic terminology and guardian policy. Native-speaker sign-off and a full accessibility or legal audit are not claimed.

## Acceptance

The owner explicitly authorised publication of the updated website and documentation, including the required approval steps. The sole guardian's GitHub authorship cannot count as independent review. Any narrowly required review exception for this release is documented in [the release decision](../governance/release-exceptions/2026-10-22-v1.2.0.md); all non-review protections remain enabled and the original review policy must be restored before the release is tagged.

The corresponding website release temporarily pauses its Implementation menu and inbound links. This is a presentation decision; these open functional guides remain available as operating knowledge. The website must import the exact accepted main commit rather than this proposal branch.
